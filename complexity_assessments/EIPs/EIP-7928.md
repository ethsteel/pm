#### Special Considerations

- **Spec churn fed back into tests.** The EIP was repeatedly amended during implementation as edge cases surfaced — selfdestruct semantics (to self / precompile / system contract / 7702-delegated beneficiary), coinbase on empty blocks and zero-tip blocks, system-call caller filtering (`SYSTEM_ADDRESS` must not appear from system operations alone), index width (uint32 → uint64), `bal_items` gas-limit constraint, ITEM_COST buffer. Each round of EIP updates required test re-baselines.
- **Inclusion is gas-cliff sensitive.** "If you don't have gas to access an address, it doesn't exist in the BAL." This collapses the *consensus check* and the *gas check* into a single point that must be tested at OOG-1, OOG, and success for every state-accessing opcode, in cold and warm variants, in static and non-static contexts, and with and without 7702 delegation in the chain. The optimization where DELEGATECALL/STATICCALL/CALLCODE perform their static-cost check before any state access means the delegation target legitimately disappears from the BAL at the boundary — easy to get wrong.
- **Write-shadows-read and net-zero filtering are framework-wide invariants.** A slot written in any successful frame must not appear in `storage_reads` for that account in that tx; an SSTORE chain whose final value equals the pre-tx value must produce neither a `storage_changes` entry nor a `storage_reads` shadow (but the slot still appears in `storage_reads` if it was observed). Nested DELEGATECALL frames that revert and reinstate the pre-value require correct merge semantics. Several real client bugs in this area were caught by these tests.
- **Cross-block state must not leak.** Internal EVM state used for precompile handling (RIPEMD-160 Parity Touch Bug, EIP-161) had to be reset between blocks so phantom precompile entries don't appear in BAL.
- **Invalid-BAL surface is large.** A dedicated `test_block_access_lists_invalid.py` exercises missing/extra/wrong/duplicate entries across every field type, ordering violations, header-vs-BAL hash mismatch, missing-withdrawal-only accounts, spurious coinbase, surplus `SYSTEM_ADDRESS`, and gas-limit boundary. All require new `INVALID_BLOCK_ACCESS_LIST` / `INVALID_BAL_HASH` / `BLOCK_ACCESS_LIST_GAS_LIMIT_EXCEEDED` error-mapping in every client wrapper.
- **Framework additions are substantial.** `packages/testing/.../block_access_list/` adds ~2.4 KLOC of expectation, modifier, t8n, and account-absent-value primitives — `BlockAccessListExpectation`, `BalAccountExpectation`, `BalAccountAbsentValues`, plus a modifier DSL used to construct invalid BALs from valid ones. These primitives are now a permanent extension of the testing framework.

#### Notes

- The benchmark suite gained two new sub-trees (`tests/benchmark/stateful/eip7928_block_level_access_lists/` and `tests/benchmark/compute/eip7928_block_level_access_lists/`); future benchmark work should treat BAL generation cost as a first-class metric.
- The implementation lives entirely in `src/ethereum/forks/amsterdam/` (`block_access_lists.py`, `state_tracker.py`, `blocks.py`, `fork.py`, `exceptions.py`, `vm/__init__.py`); cross-fork reuse is bounded — earlier-fork tests that exercise BAL semantics import the expectation from the Amsterdam-aware framework path and are run as Amsterdam-fork test vectors.
- Several tests in `test_cases.md` are still 🟡 Planned (e.g. `test_bal_create2_to_A_read_then_selfdestruct`, `test_bal_create2_selfdestruct_then_recreate_same_block`, `test_bal_selfdestruct_send_to_sender`) — these are tight-corner cases worth coordinating closely with clients before fork freeze.
